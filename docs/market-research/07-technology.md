# 07. 技術動向

## 1. 加工カメラアプリに必要な技術要素

| 要素                     | 内容                                                            | 実現手段の例                                                                            |
| ------------------------ | --------------------------------------------------------------- | --------------------------------------------------------------------------------------- |
| カメラ制御               | プレビュー、撮影、前後カメラの切り替え、露出・フラッシュ、動画  | iOS: AVFoundation / Android: CameraX                                                    |
| リアルタイムのフィルター | LUT（色変換）、粒子、光漏れ、ビネット、にじみ、色収差、日付印字 | GPU シェーダー（Metal / Core Image / OpenGL ES / Vulkan）                               |
| 顔検出・ランドマーク     | 顔の位置・特徴点                                                | Apple Vision、Google MediaPipe Face Landmarker、ML Kit                                  |
| 美肌・補正               | 肌の平滑化、トーン補正、目・輪郭の微調整                        | 肌マスクと周辺の構造を保つぼかし（バイラテラル / ガイデッドフィルター）、または商用 SDK |
| セグメンテーション       | 人物・背景・髪・肌の分離                                        | Vision（人物セグメンテーション）、MediaPipe                                             |
| AR エフェクト            | 顔に追従するスタンプ・キャラ化                                  | ARKit Face Tracking、商用 AR SDK                                                        |
| 後から編集               | 撮影後のフィルター変更・調整・デコ                              | 撮影時と同じシェーダーパイプラインを再利用する                                          |
| 生成 AI（任意）          | AI 変身・高画質化                                               | サーバー API、または端末上の軽量モデル                                                  |

**判断の目安**

- 初期は **MediaPipe（両 OS 対応・無料）と自前のシェーダー**（本プロジェクトでは Skia の SkSL）で、「レトロフィルター＋自然な美肌」を作れます。
- キャラ化の AR エフェクトに本格的に取り組む段階で、商用 SDK を検討します（費用と効果を見て判断）。

## 3. クロスプラットフォームとネイティブの比較

| 方式                                               | 長所                                                                                                                                                                                 | 短所                                                                                                                                                    |
| -------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **iOS ネイティブ（Swift + AVFoundation + Metal）** | 最高の性能と画質。最新の API（カメラ、Vision、Core ML）を最大限に使える                                                                                                              | iOS のみ                                                                                                                                                |
| Flutter                                            | UI を共通化できる。Flutter 自体の iOS 描画は Metal 化されている [S-75]                                                                                                               | カメラのフレームを Dart 側に渡すと遅延・メモリ負荷が大きい [S-76]。映像処理はネイティブ側に残し、テクスチャを共有する設計が必要                         |
| React Native                                       | UI を共通化できる。VisionCamera（両 OS 対応のカメラライブラリでは最も成熟）と react-native-skia を組み合わせると、**SkSL シェーダーを1つ書くだけで両 OS と Web で動く** [S-78][S-80] | Skia で描いた加工は撮影画像に乗らない（v4 ドキュメントで明記）[S-78][S-81]。顔検出と Skia を同時に使うとフレームレートが落ちる、という報告がある [S-83] |
| Kotlin Multiplatform                               | ロジックを共通化し、UI と映像処理はネイティブにできる                                                                                                                                | 学習コストがかかる。iOS 側は Swift の実装が必要                                                                                                         |

**判断の目安（調査時点）**

- ターゲットの iPhone 比率は約85%（[03](03-user-trends.md)）で、カメラアプリでは**映像処理の性能が体験の質を決めます**。
- 当初は「MVP は iOS ネイティブ」を推奨していましたが、要件定義で両 OS を同時に出すことになったため、下の §5 の構成を採用しました。
- 参考値: Apple のサンプルでは、Metal による画像処理は iPhone 6 でも CPU 1.1ms・GPU 2.6ms/フレームでした [S-77]。最近の端末なら、1080p のリアルタイムフィルターは十分に現実的です。

## 4. フィルム・デジカメ質感の作り方（技術メモ）

| 質感                   | 技術                                                |
| ---------------------- | --------------------------------------------------- |
| 色味                   | 3D LUT（.cube）。フィルムやデジカメの種類ごとに作る |
| 粒子                   | 輝度に応じたノイズ（フレームごとに変化させる）      |
| 光漏れ                 | 画像テクスチャの加算合成。撮影ごとにランダム化する  |
| CCD のにじみ・ブルーム | 明るい部分を抽出し、ぼかして加算する                |
| 低画素・ガラケー画質   | 縮小・拡大、JPEG ブロックノイズ、シャープネスの調整 |
| 色収差・ビネット       | RGB のずらし、周辺の減光                            |
| 日付印字               | 7セグメント風フォントの描画と、オレンジの発光表現   |
| フラッシュ             | 中心の露出を上げ、周辺を落とし、背景を暗くする      |
| VHS                    | 走査線、色ずれ、トラッキングノイズ、タイムスタンプ  |

→ これらは**データ（LUT・テクスチャ・パラメーター）として定義できる**ので、アプリを更新しなくても新作フィルムを配信できる設計にできます（コンテンツの入れ替え運用と相性が良い）。

## 5. React Native のカメラ・描画の動向と、本プロジェクトの採用構成

### 5.1 VisionCamera と react-native-skia（2026年時点）

| 項目             | 内容                                                                                                                                                                                                                                                                                                              | 出典             |
| ---------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------- |
| VisionCamera v5  | Nitro Modules で作り直された。フレームプロセッサーのネイティブプラグインは型付きの Nitro Module になり、worklet の実行には react-native-worklets を使う。Constraints API、深度、RAW、複数カメラの同時使用、GPU によるフレームのリサイズに対応。5.1.1（2026年7月17日）、5.2.0（同年7月27日）とリリースが続いている | S-79, S-80, S-82 |
| Skia との統合    | SkiaCamera コンポーネントの `onFrame` で、フレームを SkImage として Skia のキャンバスに描く。フレームは顔検出などの処理にも使える。`takeSnapshot()` もある                                                                                                                                                        | S-80, S-81       |
| 撮影画像との関係 | v4 のドキュメントでは「Skia で描いた内容は撮影した写真・スナップショット・動画には乗らない（プレビュー専用）」と明記されていた。v5 でも乗るという情報は確認できなかった                                                                                                                                           | S-78, S-81       |
| 性能             | 公式は「描画の複雑さによっては最大500fps」としている（最良のケース）。顔検出と Skia を組み合わせるとフレームレートが落ちる、という報告がある（ベンダーのブログ）                                                                                                                                                  | S-78, S-83       |
| JS 側から使う    | React Native の New Architecture（0.76 から標準、0.82 から必須）で JSI が同期的になり、ネイティブとの間でデータを受け渡すときの直列化のコストがなくなった                                                                                                                                                         | S-84             |

### 5.2 本プロジェクトの採用構成（2026-10-24 決定）

| 層               | 採用                                                                                                                    |
| ---------------- | ----------------------------------------------------------------------------------------------------------------------- |
| アプリ           | Expo（React Native）＋ VisionCamera v5 ＋ react-native-skia                                                             |
| 加工処理         | SkSL シェーダーを `packages/filters` にまとめ、アプリのプレビュー・フル解像度での保存・Web のフィルムスタジオで共有する |
| 撮影画像への加工 | 元の写真を撮ってから、同じシェーダーを画面外でかけ直す（プレビュー専用という制約への対策）                              |
| 重い処理         | 顔の特徴点・人物の切り抜きは MediaPipe のネイティブモジュール。美肌は性能次第でネイティブに移す                         |

詳細は [要件定義 07-system-architecture](../requirements/07-system-architecture.md) を参照してください。
