# 06. 未決事項・リスク・前提

## 1. 決定事項（D-01〜D-06 は 2026-10-24）

| #    | 項目                           | 決定内容                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| ---- | ------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D-01 | コンセプト                     | 4案（フィルム / キャラ / プリ / AI）を**すべて1つのアプリにモードとして統合**する。フィルム＋美肌を土台にする                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| D-02 | プラットフォーム・技術構成     | **iOS / Android を同時に開発する。TypeScript のモノレポで、役割ごとに技術を組み合わせる**: アプリは Expo（React Native）＋ VisionCamera v5 ＋ react-native-skia、重い処理だけネイティブモジュール（MediaPipe）、社内のフィルムスタジオは React（Web）、サーバーは Firebase（TypeScript）。※当初の「Flutter で両 OS」案から変更（[07](07-system-architecture.md)）。※顔検出は D-09 で既存プラグイン（ML Kit）に変更                                                                                                                                                                              |
| D-03 | 課金                           | **フリーミアム（年額＋買い切り）**。AI はクレジット制                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| D-04 | 体制・期間                     | **個人開発で、6ヶ月で MVP**（目標は2027年4月末）                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| D-05 | 開発者のスキル                 | TypeScript / React の経験は5年                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| D-06 | シェーダーの共通化             | **SkSL（Skia）で1つのソースにする**。アプリのプレビュー・フル解像度での保存・Web のスタジオで同じシェーダーを使う（旧 Q-03 を解決）                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| D-07 | プレビューのフレームレート     | **24fps 固定**（2026-10-25）。暗い場所で露出を延ばして約16fpsまで下がるのを防ぎ、滑らかさを優先する。VisionCamera v5 は範囲指定（例: 24〜30fps）ができず固定値のみのため。明るい場所でも24fpsになる                                                                                                                                                                                                                                                                                                                                                                                             |
| D-08 | フロントカメラの保存の向き     | **プレビューどおり（鏡像）で保存**（2026-10-25）。SNOW・BeautyPlus など自撮りアプリの一般的な挙動に合わせる。設定での切り替えは設定画面を作るときに検討する                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| D-09 | 顔検出                         | **既存プラグイン `react-native-vision-camera-face-detector`（Google ML Kit, MIT）を使う**（2026-10-25）。VisionCamera v5 対応で、目の開き具合・ランドマーク・輪郭が取れ、自作のネイティブモジュールを持たずに済む。プレビューのフレーム処理の中で呼び、カメラの解析ストリームは増やさない（Android の CameraX は解析ストリームを1本しか持てないため）。MediaPipe は人物の切り抜き（PRI-04）で必要になったときに検討する                                                                                                                                                                         |
| D-10 | 状態管理                       | **Zustand だけを使う**（2026-10-27）。サーバーから取るデータ（マニフェスト・クレジット）が少なく、TanStack Query の出番がないため（YAGNI）                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| D-11 | AI の認証                      | **端末で作る256ビットの秘密鍵による匿名アカウント**（2026-10-27）。サーバーは鍵のハッシュだけを保存する。アプリに Firebase SDK とネイティブの設定ファイルを入れずに済み、設定がなくてもビルドできる。不正対策は登録数（アドレスごと）と生成回数（アカウントごと）の制限、App Check はリリース前に追加する                                                                                                                                                                                                                                                                                       |
| D-12 | 分析・クラッシュ               | **自前の API（Cloud Functions → Cloud Logging → BigQuery）に匿名イベントと JS のエラーを送る**（2026-10-27）。Analytics / Crashlytics のネイティブ SDK を使わず、送る内容を最小限に保てる。ネイティブのクラッシュはストアのクラッシュレポートで補う                                                                                                                                                                                                                                                                                                                                             |
| D-13 | プリのフィルム                 | **プリ（キラキラ）のフィルムは無料**（2026-10-27）。プリ風の補正（PRI-03）が MVP 必須のため。無料フィルムは5種になる                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| D-14 | 音量ボタンでの撮影             | **最小限のローカル Expo モジュール**（`apps/mobile/modules/volume-shutter`、2026-10-27）。既存のライブラリが旧アーキテクチャ専用のため、D-09（自作のネイティブコードを持たない）の例外とする。iOS は `AVCaptureEventInteraction`（17.2 以上）、Android は未処理のキーイベントを使う                                                                                                                                                                                                                                                                                                             |
| D-15 | コンテンツ配信のキャッシュ     | **素材は内容のハッシュ名で配信し、無期限にキャッシュする**（2026-10-27）。`manifest.json` だけ短いキャッシュにする。更新した素材が古いまま配られることがない                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| D-16 | 画像生成 AI の既定の提供元     | **Vertex AI の Gemini 画像モデル＋Cloud Vision SafeSearch**（2026-10-28、暫定）。サーバーと同じ Google Cloud プロジェクトで動き、API キーを持たずにサービスアカウントで認証でき、送った写真が学習に使われない。`AI_PROVIDER` で切り替えられるので、品質と費用を比べて最終決定する（Q-04）                                                                                                                                                                                                                                                                                                       |
| D-17 | Instagram ストーリーズへの共有 | **最小限のローカル Expo モジュール**（`apps/mobile/modules/instagram-stories`、2026-10-28）。Instagram が公開している方法（iOS はペーストボード＋`instagram-stories://`、Android は `ADD_TO_STORY` インテント＋専用の FileProvider）で、写真をステッカーとしてアプリのグラデーションの上に渡す。D-14 と同じく、既存ライブラリが要らない機能まで持ち込むための例外。Facebook のアプリ ID が必要                                                                                                                                                                                                  |
| D-18 | 人物の切り抜き（PRI-04）       | **OS と ML Kit の既製の切り抜きを最小限のローカル Expo モジュールで呼ぶ**（`apps/mobile/modules/person-segmentation`、2026-10-28）。iOS は Vision の人物セグメンテーション（追加の依存なし）、Android は ML Kit の Selfie Segmentation（顔検出と同じ ML Kit）。どちらも端末内で処理し、写真を送らない。プレビューではなく撮ったコマに対して行い、プレビューの fps に影響させない。MediaPipe（D-09 で保留）は使わない                                                                                                                                                                            |
| D-19 | 一般的な加工アプリ並みの機能   | **メイク・顔の細部・歯・クマ・ニキビ消し・体型・髪色・詳細補正・HSL・トーンカーブ・部分補正・背景ぼかし・不要物の消去・高画質化・動く／立体的な顔エフェクト・コラージュ・フォント・コンテンツの拡充・英語表示・短尺動画を T に加える**（2026-10-28）。作らないもの: ソーシャル機能（未成年保護）、全身の AR（全身の骨格推定をプレビューで動かす負荷が大きい）、3D モデルのアバター（CHR-07）、動画へのキャラ・美肌の適用（動画のフレームごとの加工はネイティブの映像処理が必要。動画にはフィルムの色だけをかける）。端末だけで行う高画質化（AI-09）も L のまま（サーバーで行う AI-11 で代える） |
| D-20 | RAW の現像 | **OS の RAW デコーダーを最小限のローカル Expo モジュールで呼ぶ**（`apps/mobile/modules/raw-develop`、2026-10-31）。react-native-skia は RAW を読めないため。iOS は Core Image、Android は ImageDecoder で、どちらも追加の依存なし。D-14・D-17・D-18 と同じく、既存ライブラリでは足りない場合の例外 |
| D-21 | 端末内の動く写真の書き出し | **既存の `modules/video-film` に、コマ画像から MP4 を作る関数を足す**（2026-10-31）。描画は他の加工と同じ SkSL シェーダー、書き出しだけをネイティブ（iOS は AVAssetWriter、Android は既に使っている Media3 Transformer）で行い、新しい依存は増やさない |
