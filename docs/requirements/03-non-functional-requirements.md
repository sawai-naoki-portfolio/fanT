# 03. 非機能要件

## 1. 対応環境

| 項目                | 要件（仮）                                             | 備考                                                           |
| ------------------- | ------------------------------------------------------ | -------------------------------------------------------------- |
| iOS                 | iOS 17 以上                                            | 2027年4月時点の利用シェアを見て最終決定する                    |
| Android             | Android 10（API 29）以上                               | Skia の GPU 描画が動くこと（Vulkan または OpenGL ES 3.0 以上） |
| Expo SDK の最低要件 | 上の値が、採用する Expo SDK の最低要件を下回らないこと | 開発開始時に確認する                                           |
| 推奨端末（iOS）     | iPhone 12 以降                                         | 性能目標を保証する対象                                         |
| 推奨端末（Android） | 2021年以降のミドルレンジ以上（Snapdragon 7 系相当）    | 性能目標を保証する対象                                         |
| 最低動作端末        | iPhone XR / Android の2019年ミドルレンジ相当           | 品質を落とした動作を許容する（下記 §2）                        |
| 画面                | 縦向き固定（MVP）                                      | タブレットは「動作する」レベルで最適化はしない                 |
| 言語                | 日本語                                                 | 英語は Phase 2。文言は最初から多言語化できる構造にしておく     |

## 2. 性能

| 項目                                                 | 目標値（推奨端末）                                                    | 最低端末                           |
| ---------------------------------------------------- | --------------------------------------------------------------------- | ---------------------------------- |
| プレビューのフレームレート（フィルム＋美肌）         | **24fps 固定を維持**（暗い場所でも下げない。D-07）                    | 24fps を維持（品質を自動で下げる） |
| プレビューのフレームレート（キャラ＋美肌＋フィルム） | 24fps を維持                                                          | 20fps 以上                         |
| アプリ起動からカメラ表示まで（コールドスタート）     | 2.0秒以内                                                             | 3.5秒以内                          |
| シャッターを押してから撮影の反応が出るまで           | 200ms 以内                                                            | 400ms 以内                         |
| 撮影から保存完了まで（フル解像度）                   | 2.0秒以内                                                             | 4.0秒以内                          |
| フィルム切り替えの反映                               | 100ms 以内（ダウンロード済みの場合）                                  | 300ms 以内                         |
| 後から編集でのフィルム再適用                         | 1.0秒以内                                                             | 2.5秒以内                          |
| AI 生成                                              | 90パーセンタイルで30秒以内。60秒でタイムアウトし、クレジットを返却    | 同じ                               |
| 発熱・電池                                           | 10分間連続でプレビューしても、熱制御によるフレームレート低下が20%以内 | 品質を自動で下げて対応             |
| メモリ                                               | 撮影・編集中のピークで 600MB 以下                                     | 400MB 以下（解像度を下げる）       |

**スレッドの原則**: フレーム処理（顔検出・Skia の描画）は worklet スレッドと GPU で行います。JS スレッドが止まって UI の操作がカクつかないようにします。

**品質の自動調整**: フレームレートが目標を下回ったら、次の順番で負荷を下げます。

1. プレビューの解像度
2. 美肌の処理の段数
3. ブルーム・粒子の精度

保存する画像は、常にフル品質で処理します。

## 3. 画質

| 項目                       | 要件                                                                                                                              |
| -------------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| プレビューと保存結果の一致 | プレビューで見た色・質感と、保存した結果が視覚的に一致すること（同じシェーダー・パラメーター・乱数シードで、画面外でかけ直す）    |
| 両 OS と Web での一致      | 同じフィルムなら、iOS・Android・フィルムスタジオ（Web）の出力の色差を ΔE（色差の指標）の平均 3 以下にする（ゴールデン画像で比較） |
| 保存形式                   | JPEG（品質90前後）。HEIC は Phase 2 で検討                                                                                        |
| 解像度                     | 端末のフル解像度で保存。ただし「低画素」系のフィルムは、意図的に低い解像度にする                                                  |
| 美肌                       | 目・眉・髪・輪郭のエッジを保つ。肌の質感（毛穴を消しすぎない）を残す                                                              |

## 4. 可用性・オフライン

| 項目                   | 要件                                                                                                         |
| ---------------------- | ------------------------------------------------------------------------------------------------------------ |
| オフライン動作         | 撮影・フィルム（同梱分とダウンロード済み分）・美肌・キャラ・プリ・編集・デコ・保存は、**オフラインでも動く** |
| オンラインが必要な機能 | AI 生成、コンテンツのダウンロード、課金、リモート設定                                                        |
| サーバー障害時         | AI モードとコンテンツの追加だけが使えなくなり、ほかの機能は影響を受けない                                    |
| サーバーの可用性       | マネージドサービス（Firebase / Cloud Run 等）の SLA に従う。個別の SLA は設けない                            |

## 5. セキュリティ

| 項目           | 要件                                                                                                                           |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| API キー       | 画像生成 API などの秘密情報は、**アプリに埋め込まない**。サーバー（プロキシ）経由で呼ぶ                                        |
| 不正利用の防止 | App Attest / Play Integrity（Firebase App Check 等）で、正規アプリからのリクエストに限定する。端末 ID 単位でレート制限をかける |
| 課金の検証     | レシートの検証と権利の判定はサーバー側（RevenueCat 等）で行う。クライアントの判定だけに頼らない                                |
| クレジット残高 | サーバー側で管理する。生成の成功・失敗とあわせて、消費・返却をトランザクションで処理する                                       |
| 通信           | すべて HTTPS（TLS 1.2 以上）                                                                                                   |
| 端末内のデータ | アプリのサンドボックス内に保存する。バックアップの対象にするかどうかは、設定で選べるようにする                                 |

## 6. プライバシー

| 項目            | 要件                                                                                                                                                                              |
| --------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 画像の処理場所  | AI モード以外は**端末内で完結**し、画像を外部に送らない                                                                                                                           |
| AI モードの画像 | 送信前に明示的に同意を取る。サーバーでは処理が終わったらすぐに削除する（ログも含め、最大24時間以内）。**学習に使わない**。生成 API の提供元も、学習に使わない条件で契約・設定する |
| 顔データ        | 顔の位置・ランドマーク・目の開き具合などの検出結果は、メモリ上でだけ処理する。保存も送信もしない                                                                                  |
| 位置情報        | 保存時に既定で EXIF の GPS を削除する                                                                                                                                             |
| 分析            | 匿名 ID と最小限のイベントに限る。広告 ID は使わない（ATT の許可は求めない）                                                                                                      |
| ストアへの申告  | App Privacy（栄養ラベル）、プライバシーマニフェスト、Google Play のデータセーフティを正確に記載する                                                                               |
| 法令            | 個人情報保護法に沿ったプライバシーポリシーを用意する                                                                                                                              |

## 7. 未成年への配慮

| 項目         | 要件                                                                                                  |
| ------------ | ----------------------------------------------------------------------------------------------------- |
| 年齢区分     | iOS は 9+ 程度、Google Play は IARC で全年齢〜12歳以上を想定する（AI モードの内容を踏まえて最終決定） |
| 課金の UI    | 価格・更新周期・解約方法をペイウォールに明記する。誤ってタップしにくい配置にする                      |
| ソーシャル   | 見知らぬ人とつながる機能は作らない                                                                    |
| 身体イメージ | 顔の変形は控えめな範囲に制限し、既定でオフ。痩身（体型の変形）機能は作らない                          |

## 8. 保守性・運用

| 項目                 | 要件                                                                                                                                                                                                      |
| -------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| コンテンツのデータ化 | フィルム・キャラ・台紙・スタンプ・AI スタイルは、データ（JSON と素材ファイル）として定義する。アプリを更新せずに追加できるようにする                                                                      |
| シェーダーの共通化   | `packages/filters` の SkSL を、アプリ（プレビュー・保存）とフィルムスタジオで共有する。プラットフォームごとにシェーダーを書き分けない                                                                     |
| 外部ライブラリの隔離 | VisionCamera・Skia の API は `apps/mobile/src/engine/` に閉じ込め、画面側から直接呼ばない（バージョンアップの影響範囲を限定する）                                                                         |
| コード品質           | TypeScript は strict モード。ESLint と Prettier を CI で強制する。ネイティブ側は SwiftLint / ktlint を使う                                                                                                |
| テスト               | packages のユニットテスト（Vitest）、シェーダー出力のゴールデン画像テスト（ヘッドレスの CanvasKit）、主要な画面のコンポーネントテスト（React Native Testing Library）、E2E（Maestro）、実機での性能テスト |
| CI/CD                | GitHub Actions で lint・型チェック・テスト・コンテンツの検証を行う。EAS Build でビルドし、EAS Submit で TestFlight / Play の内部テストへ配布する                                                          |
| ストア審査なしの更新 | EAS Update は、JS とアセットの不具合修正・UI の微調整だけに使う。ネイティブの変更や主要な機能の変更は、ストアの審査を通す（[07](07-system-architecture.md) §9）                                           |
| 監視                 | クラッシュフリー率 99.5% 以上を目標にする。AI API のエラー率・遅延・コストを監視する                                                                                                                      |
| アプリサイズ         | 初回ダウンロード 80MB 以下（素材は必要なときにダウンロード）                                                                                                                                              |

## 9. アクセシビリティ

- 主要なボタンに、VoiceOver / TalkBack 用のラベルを付ける
- 文字とボタンのコントラスト比 4.5:1 以上（写真の上に重ねる UI は影や背景で確保する）
- タップ領域は 44pt（iOS）/ 48dp（Android）以上
- 振動・音による演出は、オフにできるようにする
